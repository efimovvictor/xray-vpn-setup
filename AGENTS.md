# AGENTS.md

Правила для AI-агентов (и людей), которые правят этот репозиторий.
Читать целиком перед любым изменением скриптов.

## Что это

Два скрипта ставят **Xray-core** как локальный прокси из ссылки `vless://`
(VLESS + Reality) и по флагу (`--claude`, `--opencode`) направляют в него
Claude Code или opencode.

```
Claude Code / opencode → 127.0.0.1:<PORT> (Xray) → <SERVER_IP>:443 (VLESS+Reality) → интернет
```

Скрипты **не** делают: TUN, системный прокси, маршруты, правила фаерфола,
службы, драйверы. Прокси слушает только `127.0.0.1`, чтобы офисный VPN
(split tunneling) продолжал работать. По умолчанию приложения не трогаются:
Xray настраивается, `settings.json` и opencode — только по явному флагу.

## Файлы

| Файл | Роль |
|---|---|
| `setup-windows.ps1` | установка/удаление на Windows, PowerShell 5.1 |
| `setup-macos.sh` | установка/удаление на macOS, bash 3.2 |
| `README.md` | единственная инструкция, по-русски |
| `AGENTS.md` | этот файл |

## Жёсткие правила

1. **Никаких секретов в репозитории.** Ни IP, ни UUID, ни `pbk`/`sid`, ни base path
   панели, ни имён пользователей, ни e-mail. В документации — плейсхолдеры:
   `<SERVER_IP>`, `<PANEL_PORT>`, `<BASE_PATH>`, `<путь>`. Ссылка `vless://` содержит
   UUID клиента = доступ к серверу, поэтому её нельзя ни логировать, ни коммитить.
2. **Только loopback.** Listen-адрес всегда `127.0.0.1`. Не добавлять `0.0.0.0`,
   `::`, LAN-адреса — даже «на время отладки».
3. **Не трогать систему.** Запрещено: `netsh winhttp`, системный прокси Windows,
   `scutil --proxy`, `networksetup -setwebproxy`, `route add`, правки фаерфола,
   установка служб/демонов вне `LaunchAgents` пользователя.
4. **`localhost` в ссылке — ошибка, а не предупреждение.** Оба скрипта обязаны
   завершиться с кодом 1, ничего не записав, если хост ссылки `localhost`,
   `127.0.0.1` или `::1`. Это защита от ссылок, сгенерированных в панели,
   открытой через SSH-туннель.
5. **`~/.claude/settings.json` только мержится.** Сохранять все существующие ключи
   (`model`, `statusLine`, `enabledPlugins`, `extraKnownMarketplaces`, чужое `env`).
   Перед записью — копия `settings.json.bak-YYYYmmdd-HHmmss`. При удалении убирать
   только три ключа и только если их значения совпадают с теми, что поставил скрипт;
   пустой `env` удалять целиком.
6. **Скрипты — ASCII-only.** Никакой кириллицы, эмодзи и умных кавычек в `.ps1`/`.sh`:
   Windows PowerShell 5.1 читает файл без BOM в системной кодировке и ломает вывод.
   Сообщения пользователю — по-английски, документация — по-русски.
7. **Паритет платформ.** Любое изменение поведения делать в обоих скриптах:
   одинаковые флаги, дефолты, тексты ошибок, коды возврата, порядок шагов.
8. **Без новых зависимостей.** Только то, что есть в системе: PowerShell 5.1,
   `curl`/`Invoke-WebRequest`, `tar`, `python3` (на macOS — опционально).
   Никаких `npm`, `pip`, `brew`, сторонних бинарников.

## Windows: `setup-windows.ps1`

- Совместимость с **PowerShell 5.1**: нельзя `??`, `?.`, тернарный `? :`,
  `ForEach-Object -Parallel`, `ConvertFrom-Json -AsHashtable`, `-NoEnumerate` и прочее
  из PS 7. Проверять синтаксис парсером (см. ниже), а не «на глаз».
- `$ErrorActionPreference = 'Stop'`; фатальные ошибки — `throw` → `Error: ...` → `exit 1`.
- Права администратора не нужны. `sudo` для `.ps1` на Windows не работает
  (`0x800700C1`) — не предлагать его в документации.
- Пути по умолчанию:
  - установка: `%USERPROFILE%\xray` (`xray.exe`, `config.json`, `start-xray.vbs`);
  - автозапуск: ярлык `XrayProxy.lnk` в Startup;
  - настройки: `%USERPROFILE%\.claude\settings.json`.
- Папку Startup брать через `[Environment]::GetFolderPath('Startup')`, но с фолбэком
  на `$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup` (в некоторых
  окружениях первый вариант возвращает пустую строку).
- JSON писать `ConvertTo-Json -Depth 20` в UTF-8 **без BOM** (`UTF8Encoding($false)`).
- Остановка процесса — с ожиданием реального выхода (до 10 с), удаление папки —
  с повторами: `Stop-Process` возвращается раньше, чем Windows отпускает `.exe`,
  иначе `Access to the path 'xray.exe' is denied`.
- Удаление не должно быть фатальным из-за одного занятого файла: предупредить
  и продолжить, а не оставить установку в половинчатом состоянии.

## macOS: `setup-macos.sh`

- **bash 3.2** (системный): без ассоциативных массивов, `mapfile`, `${var,,}`,
  `[[ ... =~ ... ]]`-зависимостей. `set -eu`, ошибки — через `die`.
- Пути: установка `~/xray` (переопределяется `XRAY_DIR`), автозапуск —
  `~/Library/LaunchAgents/local.xray.plist`, метка `local.xray`,
  настройки — `~/.claude/settings.json`.
- Управление агентом: `launchctl bootstrap|bootout|kickstart gui/$(id -u)`.
- `python3` может быть заглушкой Command Line Tools и вызывать диалог установки:
  использовать только после проверки `xcode-select -p`, иначе — запасной путь
  через `sed`/ручной текст, но без падения скрипта.
- Не требовать `sudo` и не писать вне `$HOME`.

## Общая логика (менять только синхронно)

| Флаг Windows / macOS | Поведение |
|---|---|
| `-Link` / `--link` | без него: оставить существующий конфиг, иначе спросить |
| `-Port` / `--port` | локальный порт, по умолчанию **12345**, HTTP и SOCKS5 на одном порту |
| `-NoAutostart` / `--no-autostart` | не ставить автозапуск |
| `-Claude` / `--claude` | прописать три переменные в `~/.claude/settings.json` |
| `-OpenCode` / `--opencode` | прописать три переменные в окружение сервиса opencode |
| `-Desktop` / `--desktop` | запускалка Claude Desktop с `--proxy-server` (Windows: ярлык в меню Пуск, macOS: `~/Applications/Claude (Xray proxy).app`) |
| `-Update` / `--update` | перекачать ядро, конфиг сохранить |
| `-Uninstall` / `--uninstall` | остановить, убрать автозапуск, папку, свои ключи из интеграций и запускалку Claude Desktop |

Без `-Claude`, `-OpenCode` и `-Desktop` скрипт не трогает ни `settings.json`, ни opencode, ни Claude Desktop:
установка Xray — самостоятельная операция. `-Uninstall` флаги интеграций
игнорирует и чистит обе, но удаляет только значения, равные локальному прокси.

Порядок шагов одинаковый: проверить ссылку → скачать/проверить ядро → собрать
`config.json` → `run -test -c config.json` → автозапуск → `settings.json` (с
`--claude`) → opencode (с `--opencode`) → запуск → проверка туннеля реальным
HTTPS-запросом.

Конфиг: локальный inbound `mixed` (HTTP + SOCKS5, без авторизации) на
`127.0.0.1:<PORT>` и один outbound `vless` с `reality` + `tcp` + `xtls-rprx-vision`.
Параметры `spx` и `support-x25519mlkem768` из ссылки игнорируются — они не нужны
Xray-core.

### Интеграция Claude Desktop

- Приложение не трогается: создаётся только отдельная запускалка с `--proxy-server=<url>`.
  Системный прокси и файлы приложения не меняются.
- Windows: пакет ищется через `Get-AppxPackage` по `PackageFamilyName -like 'Claude_*'`
  **при каждом запуске ярлыка** (путь содержит версию), исполняемый файл — `app\claude.exe`.
  Нет пакета — предупреждение, код 0.
- Удаление: только если запускалка содержит `--proxy-server=`; чужие файлы не трогать.

### Интеграция opencode

- Только через CLI, без правки его файлов: `opencode service set env HTTP_PROXY <url>`
  (первый аргумент — ключ `env`, второй — имя переменной, третий — значение).
- Писать все три переменные: `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`. Без `NO_PROXY`
  CLI теряет связь с собственным сервисом (loopback идёт через прокси).
- После записи вызывать `opencode service start`: смена переменных останавливает
  сервис. Ошибки этой интеграции не фатальны — предупредить и дать ручную команду;
  установка Xray не должна из-за них падать.
- Нет `opencode` в `PATH` — тоже предупреждение, а не ошибка.
- При удалении снимать переменную только если `opencode service get env` отдаёт
  ровно наше значение (вывод — JSON, пустое окружение = `{}`). Затем снова `start`.
- Не писать shell-профили (`~/.zshrc`, `$PROFILE`) и не выставлять переменные
  глобально: только там, где их читает сам инструмент.

## Старые настройки после смены порта

Если порт в конфиге сменился (или переехали на новый хост), но флаг интеграции
(`--claude` / `--opencode`) не передан — скрипт не меняет приложение, но предупреждает:
`claude code still points at ...`, `opencode still points at ...`. Чинить — зановым
запуском с тем же флагом, который был использован до смены порта.

## Проверка перед коммитом

```powershell
# синтаксис PowerShell
$p = '.\setup-windows.ps1'
$e = $null
[void][System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $p), [ref]$null, [ref]$e)
if ($e) { $e | ForEach-Object { "$($_.Extent.StartLineNumber): $($_.Message)" } } else { 'OK' }
```

```bash
bash -n setup-macos.sh
```

Обязательные сценарии:

1. Ссылка с `@localhost:443` → код 1, файлы не изменены (проверить по mtime).
2. Ссылка с реальным IP → установка, `run -test` = OK, туннель отдаёт IP сервера.
3. Повторный запуск без `-Link` → конфиг сохранён, порт/настройки не потеряны.
4. `-Uninstall` дважды подряд → второй запуск не падает, `settings.json` валиден,
   остальные ключи на месте, папка удалена.
5. macOS-ветку при отсутствии Mac проверять стабами (`uname`, `launchctl`, `xattr`,
   `opencode`, `curl`) в отдельной временной `$HOME`; plist валидировать `plistlib`.
6. `--opencode` без `opencode` в `PATH` → предупреждение, код 0, Xray работает.
7. `--uninstall` после `--opencode` снимает переменные только при совпадении
   значений; чужие `HTTP_PROXY`/`NO_PROXY` остаются на месте.
8. Повторный запуск без флагов не добавляет прокси туда, где его не было.

Проверка туннеля (не печатать ссылку и UUID в вывод):

```powershell
curl.exe -s -x http://127.0.0.1:12345 https://api.ipify.org
```

## Документация

- `README.md` — один связный документ: сервер → клиент → Claude Code и opencode → ежедневно →
  диагностика → безопасность. Не разбивать на файлы и не дублировать разделы.
- Держать объём умеренным (ориентир — до ~250 строк). Новая деталь добавляется
  только если без неё читатель ошибётся; историю изменений и «как я отлаживал»
  в README не писать.
- Все команды — работоспособные, с плейсхолдерами вместо личных данных.
- Предупреждение про `localhost` в ссылке должно остаться минимум в двух местах:
  доступ к панели и получение ссылки.

## Коммиты

- Один коммит = одно смысловое изменение (скрипт + его отражение в README).
- Сообщение в повелительном наклонении, по-английски: `Refuse links that point at localhost`.
- Не коммитить: бинарники Xray, `config.json`, `*.lnk`, `*.bak-*`, реальные ссылки,
  логи, скриншоты с IP.

## Чего не делать

- Не добавлять TUN/system-proxy/route-режимы «для удобства».
- Не ослаблять проверку ссылки и не превращать ошибки в предупреждения.
- Не перезаписывать `settings.json` целиком и не терять незнакомые ключи.
- Не менять дефолтный порт `12345` в одном скрипте без второго и без README.
- Не добавлять телеметрию, аналитику и загрузки с доменов, кроме релизов
  `XTLS/Xray-core` на GitHub.
- Не выполнять на машине пользователя установку, переустановку или удаление
  без явной просьбы: скрипты меняют автозапуск и настройки Claude Code и opencode.
